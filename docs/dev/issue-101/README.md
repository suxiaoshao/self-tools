## 数据权威与层级操作

### parent_id 拥有关系，path 是派生值

- `collection.id` 标识节点，`parent_id` 是唯一的父子关系事实源；根节点为 NULL。
- `path` 保留现有持久化列与唯一约束，是由祖先名称与当前 name 推导的投影。根路径为 `/{name}/`，后代继续沿用斜杠分隔及末尾斜杠；保留现有名称验证与字面 `%` / `_` 语义。
- 自身、祖先、后代、删除集合和更新范围一律按 ID / parent_id 计算，禁止用旧 path 前缀判定关系。
- 创建节点时从真实祖先名称链计算路径。bookmarks 移动 / 两服务重命名时，以新父节点的真实祖先名称链和新名称为起点，重算目标及其实际后代的路径。
- 同一 parent_id 下的同名节点按关系及 name 检查冲突，避免旧路径漂移允许创建重复兄弟节点。
- 移动到自身或真实后代沿用 `parentId` 的 ValidationFailure；明确指定但不存在的目标或父节点沿用 MissingResources。路径冲突沿用各服务已有 ConflictReason，不改 SDL。
- 已存储的环或缺失祖先属于数据不变量故障。对受影响的祖先链、目标子树完整检查后再执行写入；发现此类故障返回受控 INTERNAL 与 requestId，并回滚，不暴露原始路径或数据库原因，也不将其伪装为用户参数错误。
- 单纯的旧路径漂移不决定节点归属：明确的重命名 / 移动会按真实关系重算目标子树的派生路径，不触碰仅有相似旧前缀的其他节点，不隐式执行全库修复。受影响范围之外的其他根不因本次操作而被改写。

### 有限遍历与先计划后写入

每个服务在私有 application 范围内拥有层级逻辑；repository 负责读取必要节点及执行 SQL，GraphQL 不接触数据库或树算法。可以在写事务内一次读取仅包含层级所需字段的快照，建立按 id / parent_id 索引的结构；本轮不新增跨服务通用 CRUD 或树 trait。

祖先链和子树使用显式队列 / 栈与 visited（必要时区分正在访问与已完成）检测异常，避免递归函数造成栈溢出。路径构造、后代更新和删除规划都必须有限终止。验证针对操作依赖的祖先和真实子树，不把不相关根的异常自动扩大成所有写入不可用。

移动 / 重命名先验证拓扑、计算全部目标路径并检查冲突，再在同一事务内写入。唯一约束仍是最终并发防线；受影响路径先在事务内写入经过占用检查的临时值，再写最终路径，避免有效的路径交换被立即唯一约束拒绝。临时值不会在提交后的状态中保留。发生 SQL 故障或拒绝时不能留下部分已更新的子树。无需更改名称、parentId 的 GraphQL 参数或增加公共版本号。

删除目标不存在继续返回当前幂等成功标识。目标存在时，先取得并验证真实子树，再按子节点先于父节点的顺序删除成员关系和节点；可使用有界批次，但不能对每个子节点再次递归发起一个应用用例。遇到异常拓扑时整次操作拒绝，不尝试猜测应断开哪条边，也不部分删除作为自动修复。

## 删除与并发合同

| 操作                        | 删除范围与顺序                                                                                 |
| --------------------------- | ---------------------------------------------------------------------------------------------- |
| 删除 Novel                  | 阅读记录、小说评论、collection_novel、章节 → 小说。保留共享 Author、Tag 和 Collection。        |
| 删除 Author                 | 按上述完整小说清理处理其所有小说 → 作者；保留共享 Tag / Collection。                           |
| 刷新移除小说 / 章节         | 复用现有完整小说清理；移除章节前清理对应阅读记录。抓取仍在数据库临界区外，写入阶段重读并验证。 |
| 删除 bookmarks Collection   | 删除真实子树的 collection_novel → 子节点到父节点的 Collection；不删除小说。                    |
| 删除 collections Collection | 删除真实子树的 collection_item → 子节点到父节点的 Collection；不删除 Item。                    |
| 删除 Item                   | collection_item → Item；不删除 Collection。                                                    |

复用现有非级联外键和应用显式删除顺序，不新增 cascade、parent_id 外键、自定义约束 trigger 或 schema 迁移。当前公开写入入口由应用验证和既有事务锁维护层级不变量；直接 SQL 写入不属于受支持的业务写入入口，异常数据的防御不能宣称为数据库拒绝任意外部非法写入。

bookmarks 保留 `write` 中固定表顺序的 SHARE ROW EXCLUSIVE 锁；collections 保留现有 collection 与 item/collection_item 锁顺序。所有影响决定的检查、节点快照与最终写入都在取得锁之后，事务结束时释放，不跨公网 await 持有连接。本次竞争回归确认既有锁策略满足目标不变量，未改变锁粒度。

## 数据与迁移边界

当前核查无脏数据，且剩余修复不需要改变表结构，因此不增加清理迁移、后台自动修复或新的管理 CLI。实现阶段使用专用测试库构造异常数据，以验证失败边界；不得向个人业务库注入测试环或漂移路径。

其他部署若实际存在异常数据，应先只读确认具体 ID、归属和预期父子关系，再为那批数据制定明确的修复与回滚方案。本计划不授权猜测父节点、删除异常记录或覆盖业务库。路径仍为持久化派生值，相关设计与应用入口应同步进 server README，不能形成第二套路径事实源。
